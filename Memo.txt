# Resumen — Liga de Fútbol Rural (app web)

## 1. Qué es el proyecto

App web de gestión de una liga de fútbol rural (Torneo Jorge Oscar Romagnoli), un solo archivo HTML (`demo5.html`, ~2200+ líneas), vanilla JS + CSS, sin frameworks, bajo la marca **Elemen7** de Cristian. Actualmente usa un `mockDB` en memoria (sin backend real todavía).

**Estructura:** 9 equipos (La 14, Veterano, Unión es Fuerza, Arboledas, Agrario, La 8, Defensores de Guglieri, Ibarra, Vallimanca), 2 categorías (Primera y Segunda), 2 rondas (ida y vuelta). Secciones públicas: Fixture, Posiciones, Copa, Goleadores, Suspendidos, Archivo, Institucional. Panel de Admin con login (usuario/contraseña hardcodeado `admin`/`admin` por ahora).

## 3. ⚠️ Bug recurrente importante — para tener en cuenta a futuro

El script usa `<script type="module">`. Esto significa que una función declarada como `function foo(){}` **no** queda colgada de `window`, así que cualquier `onclick="foo()"` o `onchange="foo()"` puesto directo en el HTML **no la encuentra** (tira `ReferenceError: foo is not defined` en la consola, en silencio para el usuario — el botón/filtro simplemente "no hace nada").

**Este bug apareció y se repitió varias veces** (Fixture, Partidos, Suspensiones, Goleadores) porque cada función nueva hay que exponerla explícitamente. El patrón correcto que se usó para arreglarlo:

```js
function miFuncion(){ ... }         // declaración normal (funciona para llamadas internas del módulo)
window.miFuncion = miFuncion;        // exposición aparte (para que el onclick/onchange del HTML la encuentre)
```

**Antes de dar por terminada cualquier función nueva que se llame desde un atributo `onclick`/`onchange` en el HTML, hay que exponerla a `window`.** Al final de esta sesión se corrió un script de auditoría que revisa esto automáticamente en todo el archivo (ver sección 6) — recomiendo pedirle a Claude que lo corra de nuevo después de cualquier cambio grande.

## 4. Corrección de datos reales del torneo (ya aplicada en el archivo)

Se cruzaron los resultados contra notas reales del Diario La Mañana (diariolamanana.com.ar) para validar la tabla de posiciones. Se encontraron y corrigieron dos errores de carga:

1. **Fecha 3 Segunda, Unión es Fuerza – Vallimanca**: el partido se jugó y se informó 2-1 a favor de UeF (así está guardado, con los goleadores reales). Pero la liga aplicó una **sanción administrativa posterior**: le dio los 3 puntos a Vallimanca y anuló los goles de ese partido para la tabla. Esto se implementó con dos campos nuevos en el registro del partido: `sancionGanador:'Vallimanca'` y `sancionAnulaGoles:true`, que `calcStats()` respeta sin tocar el resultado real ni los goleadores.
2. Anteriormente se creía que había una sanción en **Unión es Fuerza – Veterano (Fecha 6 Segunda)** — se confirmó que **no existe tal sanción**, ese partido vale tal cual se jugó (1-0 a favor de UeF). Fue una confusión de una charla anterior.

La tabla de posiciones actual (tras Fecha 8, con Fecha 9 aún pendiente de jugar) fue validada célula por célula contra el diario y coincide 100% en ambas categorías.

## 5. Pendiente — Firebase (lo próximo a encarar)

Ya se habló bastante de esto pero **todavía no se implementó nada**. Decisiones ya tomadas:
- **Login/Auth**: Firebase Authentication real (email + contraseña), reemplazando el admin/admin hardcodeado.
- **Sincronización**: en tiempo real (varios admins viendo cambios en vivo, con `onSnapshot`).
- Cristian **todavía no creó el proyecto de Firebase**. Se le dieron instrucciones paso a paso (crear proyecto en console.firebase.google.com, habilitar Firestore, habilitar Authentication con email/contraseña, registrar la app web y copiar el bloque `firebaseConfig`).

**Dato técnico clave para cuando se implemente:** toda la capa de datos de la app pasa por 6 funciones nomás (`getAll`, `getCfg`, `setCfg`, `addItem`, `updItem`, `delItem`, más `addItems`/`delItems`/`clearAll` agregadas después para operaciones en lote) — conectar Firebase implica reescribir solo esas funciones para que hablen con Firestore en vez del array en memoria (`mockDB`), sin tocar el resto de las ~2200 líneas de UI. Bajo riesgo, cambio bien contenido.

**Falta también:** migrar los datos actuales (equipos, partidos, sponsors, jugadores) a Firestore una vez conectado, para no perder lo ya cargado.
